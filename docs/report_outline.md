# 线程安全型队列课程设计报告提纲

## 1. 课题背景与设计目标

本课程设计实现一个线程安全型队列。队列支持多个线程同时执行入队、出队、查找、打印等操作，并通过读者-写者模型保证并发访问的正确性。

设计目标：

- 自行实现链式队列结构，不使用 `std::queue` 替代核心数据结构。
- 入队、出队、清空属于写操作，必须独占访问队列。
- 查找、打印、快照、长度统计属于读操作，允许多个读者并发访问。
- 通过自动化单元测试和集成测试验证正确性，测试规模达到万次级别。

## 2. 数据结构设计

队列节点结构：

```cpp
struct Node {
    int data;
    Node* next;
};
```

队列维护三个核心状态：

- `front`：指向队头节点。
- `rear`：指向队尾节点。
- `count`：记录当前节点数量。

空队列满足：

```text
front == nullptr
rear == nullptr
count == 0
```

非空队列满足：

```text
front != nullptr
rear != nullptr
rear->next == nullptr
```

## 3. 同步与互斥机制

本设计使用 C++17 标准库中的 `std::shared_mutex` 实现读者-写者同步。

- 读操作使用 `std::shared_lock<std::shared_mutex>`。
- 写操作使用 `std::unique_lock<std::shared_mutex>`。
- 多个读者可以同时持有共享锁。
- 写者必须独占锁，因此写者执行时没有其他读者或写者访问队列。

没有使用普通 `std::mutex` 保护所有函数，因为普通互斥锁会让所有读操作串行执行，不能满足多个读者并发访问的要求。

## 4. 主要函数设计

### EnQueue

1. 获取写锁。
2. 创建新节点。
3. 如果队列为空，`front` 和 `rear` 都指向新节点。
4. 如果队列非空，把新节点接到 `rear->next`，再更新 `rear`。
5. `count++`。

### DeQueue

1. 获取写锁。
2. 如果队列为空，返回 `false`。
3. 保存队头节点和队头数据。
4. `front` 后移。
5. 如果删除后队列为空，设置 `rear = nullptr`。
6. 删除旧队头节点，`count--`。

### Find

1. 获取读锁。
2. 从 `front` 开始遍历。
3. 找到目标值返回 `true`。
4. 遍历结束仍未找到则返回 `false`。

`Find` 不返回节点指针，因为释放读锁后，其他线程可能删除该节点，返回裸指针会产生悬空指针。

### Clear

1. 获取写锁。
2. 从队头开始逐个删除节点。
3. 设置 `front = nullptr`、`rear = nullptr`、`count = 0`。

## 5. 测试设计

单元测试：

- 初始化状态检查。
- 单线程 FIFO 顺序检查。
- 空队列出队检查。
- 查找存在元素和不存在元素。
- 捕获 `std::cout` 检查 `Print` 输出包含队列元素顺序。
- 清空后复用队列。

集成测试：

- 多生产者线程同时入队。
- 多消费者线程同时出队。
- 生产者、消费者、读者混合运行。
- 多线程随机压力测试。

读者并发证明：

- 启动多个只读线程。
- 在共享读锁持有期间使用原子变量记录同时活跃读者数量。
- 若最大活跃读者数大于 1，说明读者之间确实可以并发。

## 6. 问题与心得

需要重点说明：

- 只用普通互斥锁虽然能保证线程安全，但不能实现读者并发。
- 链表节点删除时必须正确维护 `front`、`rear` 和 `count`。
- 集成测试不能依赖人工观察输出，必须通过计数、顺序和结构检查自动判断结果。
